> 日期：2026-10-28

## 1. 执行摘要

dc-nba 已经具有 Elo、效率评级、阵容影响力预测、赛季模拟、模型实验室、逐场时间顺序回放，以及博彩收盘盘口对照。**不建议推倒重建或直接植入大型外部投注系统。**

从当前 README 可见：
- `server/lab.mjs` 提供逐场结果与参数化历史回测。
- `data/backtest.json` 约含 6,150 场历史比赛，实验室可比较模型。
- 项目已能对照约 4,908 场比赛的收盘盘口。
- README 报告模型胜负命中率 66.3%，盘口对应约 68.4%；模型相对盘口选边的让分命中率 49.1%，低于 -110 赔率约 52.38% 的盈亏平衡点。
- 有 `npm run odds:history` 和 `npm run dataset`，说明历史盘口采集与数据合并部分已经存在。
- 用户近期截图的 56 场测试：Brier 0.209、Log Loss 0.600、分差 MAE 11.6、总分 MAE 15.1。这个样本**不能**外推为正收益。
  
**核心结论：** dc-nba 当前主要缺口不是「预测准确率面板」，而是能否按当时真正可获得的价格完成可复现、有置信区间的模拟投注回测。此前 49.1% 的盘口比较表现更提示应先验证是否存在正收益机会，而非先优化下注金额。

## 4. 历史赔率数据：第一优先级

已有 ESPN 收盘盘口数据先做完整性审计，避免重复抓取。需要形成逐场逐市场的字段：
`game_id`, `tipoff_at`, `model_version`, `prediction_at`, `bookmaker`, `market`, `selection`, `line`, `american_odds`, `decimal_odds`, `quote_at`, `is_closing`, `source`。

候选补充数据：
- The Odds API: https://the-odds-api.com/historical-odds-data/ （按官方价格、地区、历史时间范围验证）。
- Betfair Historical Data: https://historicdata.betfair.com/ （交易所数据与美国博彩公司赔率不可简单等同）。

每笔记录必须满足 `quote_at <= prediction/decision cutoff < tipoff_at` 的合理时间逻辑。收盘赔率可单独用于 CLV 或盘口对标，但如果预测早于收盘，则不能默认该报价可用于当时投注。缺少真实价格时输出「ROI 不可计算」，不能假设统一 -110 并称其为历史实际收益；统一价格仅能作为清楚标识的情景模拟。

## 5. 建议新增的核心能力

### 5.1 赔率与概率

- 美式赔率转十进制赔率与盈亏平衡概率。
- 双侧价格去水（No-vig），明确两边同一时间、同一博彩公司及市场。
- `edge = model_probability - break_even_probability`，不能把 Edge 当作 ROI。
- `EV_per_unit = p * (decimal_odds - 1) - (1-p)`，仅适用于无 push 的二元胜负市场；让分和大小分需显式考虑 push 及退款概率。
- Spread 和 Totals 需要**覆盖比分误差分布**的概率估计与校准，不能仅将均值/预测分差视作胜率。

### 5.2 回测结算

支持 Moneyline、Spread、Totals；下注结果支持 win/loss/push/void，延期比赛/取消及赛事特殊规则须可配置。输出投注流水、投注数、有效场次覆盖率、净利润、总投注额、ROI（总净利润/总投注额）、胜率、最大回撤和资金路径。

### 5.3 策略与资金管理

在完全相同且可用的历史数据上比较：
1. 无优势筛选的固定本金基线。
2. Edge/EV 阈值策略。
3. 分数 Kelly（1/4、1/2），设置单注限额、总体敞口上限，不允许负仓位、杠杆或未来数据。

先用固定金额策略识别模型是否优于市场，之后再讨论资金配置。不要用资金管理算法「制造」预测优势。

### 5.4 统计验证

- 时序切分、rolling/walk-forward、参数在验证集选取，独立测试集只用于最后检验。
- 赔率分档、Edge 分档、主客队、背靠背、赛季阶段以及盘口市场分组分析。
- Brier、Log Loss、可靠性曲线，检查校准与赔率价格表现是否同步提升。
- ROI 及市场优势置信区间，可按比赛日或赛季做 block bootstrap；多种策略筛选须报告多重比较风险。
- 报告样本规模、报价覆盖率、模型版本和数据时间戳；56 场结果只作为初步诊断。

## 6. dc-nba 集成建议

延续既有 Node/ESM/worker_threads 结构。目录仅为建议，以现有代码风格为准：

```
server/
  odds-eval.mjs       # 赔率格式、去水与概率检验
  bet-settlement.mjs  # 盘口结算
  bet-strategies.mjs  # 固定金额、Edge、EV、Kelly
  bet-backtest.mjs    # 历史时间线和逐注回测
  bet-stats.mjs       # ROI、CLV、回撤、区间
tests/
  betting-*.test.mjs
docs/
  nba-betting-quant-research.md
```

这些功能应直接消费实验室逐场结果和已有赔率数据，不复制重放算法。使用当前缓存和工作线程机制执行计算；不要干扰已有 `npm run backtest`、`npm run odds:history`、`npm run dataset` 或对外服务。

UI 在「模型实验室」内添加模拟投注分析标签：ROI、净利润、最大回撤、平均 CLV、策略表现、收益曲线、概率校准图、明细列表；缺价或价格不匹配给出明显警告。用户必须能选择训练/验证/独立测试范围，禁止默认展示调参后样本内最佳收益作为可投资结论。

## 7. 实施顺序（明确可交付）

**P0：数据和结果核验**
- 列出已有字段、缺失价格、市场覆盖率、历史赛季范围。
- 复核 README 所称 49.1% 盘口选边命中率，解释其计算公式与样本定义。
- 输出历史价格是否可用于真实 ROI 的审计结果。

**P1：可信回测 MVP**
- 赔率转换/结算/固定金额回测、资金曲线。
- 完整单元测试（正负赔率、Push、Void、不同盘口方向、重复事件、时间约束）。
- 对已有数据输出 ROI；无法计算则给出覆盖率与明确阻塞项。

**P2：策略与统计**
- Edge/EV/分数 Kelly、Walk-Forward、置信区间、CLV。
- 比较模型、市场基准和选择性投注策略，不在最终测试集调参。

**P3：UI 和扩展**
- 在原有模型实验室增设投注研究面板；继续评估第三方历史赔率 API 的成本收益。
- 保持模拟研究模式，禁止启用真实资金下注。

## 8. 验收标准

- 相同数据和参数复现完全一致的逐注流水及 ROI。
- 所有模拟下注均具有明确的价格来源与决策时点。
- 缺少历史赔率时不会生成虚假的「真实 ROI」。
- 能验证模型是否在**独立测试集**上优于当时可用的市场报价。
- 能说明为什么 66% 胜负命中率不意味着盈利，及 49.1% 盘口选边意味着什么。
- 自动测试通过且不破坏当前预测/赛季模拟/模型实验室。
- 最终报告要区分「README 记载」「已复现」「待验证」三个证据等级。
