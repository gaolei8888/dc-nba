## 方法

### 模型（`server/rosterResults.mjs`）

每队强度 r_i，单位是相对联盟平均的每场净胜分。

- 先验：r_i ~ N(p_i, σ²/K)，p_i 是现阵容榜的分数（名单 × IMP × 预计分钟，含已报缺阵）。
- 每场比赛：主队净胜分 − 主场项 ~ N(r_主 − r_客, σ²/w)。
  - 主场项 1.6 分，与 `predict.mjs` 的 DEFAULT_PARAMS 相同；中立场为 0。
  - w 是近期权重。

后验均值是带先验的岭回归解，对每支队都满足：

```
r_i = (K·p_i + Σw·adj_i) / (K + Σw)
adj_i = 本队各场「对手调整净胜分」的加权均值 = 加权均值(本队净胜分 − 主场项 + r_对手)
```

- **「先验值 K 场」**：打了 n 场后，先验权重是 K/(K+n)。K=8 时，打 8 场先验占一半，打 24 场先验占 25%。
- **对手强度用同一张后验榜**（SRS 式），用 Gauss–Seidel 迭代求解。K>0 时方程组严格对角占优，一定收敛。
- 联盟均值不变：净胜分零和，所以后验均值等于先验均值，测试锁定了这一点。
- 这就是 ESPN BPI / FiveThirtyEight「先验 + 本季结果，结果权重随场次增加」的最简形式。

### 回测（`scripts/roster-results-backtest.mjs`）

**特征**：逐场特征沿用 continuity 回测（commit bc33996）的同一套防泄漏构建，这里没有新写。

- 第 N 季只用第 N−1 季的球员价值。
- 名单与分钟只看当场之前出过场的人；第一场的名单用当场出场名单近似，见 continuityLab 注释。
- 球员价值用收缩 IMP，与线上一致。
- 先验取每队最近一次出场时的赛前阵容分。名单或分钟变了，先验跟着变，已经打出的赛果保留。

**赛前性**：每个比赛日开赛前，只用更早日期的完赛结果求后验。

**胜率换算**：Φ((r主 − r客 + 主场 + 休息项)/12)，与 lab / 生产 Elo 同口径（spreadSd 12，sd 不调）。

**协议**：

- 2021-22 只做热身，评估 2022-23 ~ 2025-26。
- 留一赛季：在其余三季上按 log loss 只选配置。
- 最终留出：在 2022-25 上选，只在 2025-26 打分一次。
- 对比 (a) 现阵容榜（K=∞）和 (b) 生产 Elo（sd=12），按场配对 bootstrap 2000 次。
- 另外报告 Brier 和净胜分 MAE（EPM 式评估）。

**预注册候选，共 96 组**，全部只按留一赛季 log loss 选：

| 族 | 依据 | 网格 |
|---|---|---|
| 基础 | 只选 K | K ∈ {1,2,3,4,5,6,8,10,12,15,20,25,30,40,60,100} |
| 先验下限 floor | ESPN BPI：先验权重逐渐变小，但不会降到 0 | 先验权重 = max(K/(K+n), f)，f ∈ {0.1, 0.2} × 全部 K |
| 近期加权 | KenPom：第 1 场的权重约为第 30 场的 40% | w = 0.4^(天数/60)（30 场约 60 天）× 全部 K |
| 净胜分截断 cap | 代替垃圾时间剔除。Cleaning the Glass 的定义需要逐回合数据和场上首发人数，这里只有终场比分 | \|净胜分\| ≤ {15, 20} × 全部 K |
| ★ | 以上 96 组一起选 | — |

Neil Paine 的模型大约把先验算作 15 场，网格已经覆盖了 10/15/20/30。

**采纳规则（预注册，产品需求）**：采纳需要同时满足两条：

1. 留一赛季 vs 现阵容榜的 Δlog loss 区间上界 ≤ +0.002；
2. 最终留出季不显著变差，即区间下界 ≤ 0。

对 Elo 的比较如实报告，不作为采纳条件。盘口只作参照列。

## 局限与没做到的

1. **K 与近期加权是在 2022-26 四季上选的。** 最终留出季只评一次。线上用的是四季合并选出的 K=8；留出时用的是 2022-25 选出的 K=12。近期加权族各折选 K=8–12，曲面平缓。
2. **先验的量纲系数固定为 1**（线上再乘 pace/100，约等于 1），没有调。sd 固定 12，没有调。
3. **先验本身沿用 continuity 回测的近似**：每队第一场的名单用当场出场名单代替；分钟模型常数对 2021-26 是样本内。
4. **垃圾时间**：只有终场比分，没有按 Cleaning the Glass 的定义剔除。净胜分截断验证无益，未采用。
5. **审计备注（不在本次范围，未修）**：ingest 的本季 IMP 混合（IMP_PRIOR_GAMES=20）把收缩后的上季 IMP 和未收缩的本季 SPM 混在一起，球员价值会漂移。本次的战绩修正在球队层面起作用，与这个问题无关，也不依赖它被修好。
6. 未合并、未部署。

## 影子运行预注册（2026-10-28，高磊批准接入影子模式；分支 shadow-roster-results）

线上预测仍是 Elo。本节在看到任何前向结果之前写定，影子期内不改。

### 记什么

- 新方案挂在现有的伤病报告影子模式（`server/injuryShadow.mjs`、`scripts/shadow.mjs`）同一次运行里，代码在 `server/rosterResultsShadow.mjs`。
- 两个变体：
  - `rr22`：北京 22:00 那次，用当时的「阵容+战绩」榜；
  - `rr0630`：北京 06:30 那次（`--late`），用当时的榜。榜的缺阵来自 `store.injuries`（availability = reported），所以 06:30 的伤病更新会反映进来。06:30 之前就开打的场，在 22:00 那次就记 `rr0630`，与 `r0630` 同规则。
- **主方案是 `rr0630`**。`rr22` 只报告，不作决策。
- 每行的胜率与回测用同一个函数 `rosterResults.gamePred`：
  - 胜率 = Φ((r主 − r客 + 主场 1.6（中立场 0）+ 休息项) / 12)；
  - 休息项 = (restAdjust(主) − restAdjust(客)) × 1.8，休息天数与 base 用同一份赛程推算；回测里同样有这一项。
  - r 取榜的 `total`（保留两位小数，对胜率的影响 < 0.001）。
  - 回测脚本改为调用同一个 `gamePred` 后重跑，输出逐字节不变。
- 冻结参数在 `server/roster-results-params-v1.json`（version 1）：
  - K = 12，近期加权 0.4^(天数/60)。原写 K = 8；上线前按「合并 batch1 后复核」改为 12，那时还没有任何 rr 行；
  - sd 12，主场 1.6，休息 1.8；
  - availability = reported；
  - IMP 收缩常数 `{ k: 3200, pivot: 1600 }`：与代码不符就不记；
  - 数据快照最多 36 小时。
- 每行另记：
  - 参数版本；
  - 快照 `meta.fetchedAt`（`board_fetched_at`）、伤病快照时间；
  - 用到的最后一个赛果日期（`results_through`）、近期加权基准日；
  - 双方先验与评级、主场项、休息项；
  - 榜相关源码的指纹（`board_code`，sha256 前 12 位）。
- 存在单独的表 `shadow_rr_predictions` 里，原因：线上库里 `shadow_predictions` 的 variant CHECK 已经定死，SQLite 改不了 CHECK；重建表又会被「开赛后不能记」挡住旧行。新表的规则与原表相同：只追加、重复忽略、不能删、预测字段不能改、比分只写一次、开赛后插不进。

### 赛前性

1. 喂给榜的赛程里，比赛日（美东）当天及之后的比分一律抹掉。这与回测「每个比赛日只用更早日期的赛果」相同。06:30 那次即使同日下午场已完赛，也进不了晚场的评级。
2. 近期加权的基准日固定为比赛日，与回测相同。
3. 库里兜底的触发器，违反任意一条就插不进：
   - `results_through < game_date`；
   - `results_as_of ≤ game_date`；
   - `board_fetched_at ≤ captured_at`；
   - 开赛前才能插（按真实时钟），且 `captured_at < tipoff_utc`。
4. 残余：球员本季统计栏（分钟、IMP）来自最新一次 ingest。同日已完赛的早场若已被抓进来，会经由那两队的先验、联盟均值，二阶地影响晚场。没有球队一天打两场，所以晚场双方自己的先验不受影响。已知、量小，不处理。

### 隔离

- rr 在 base / r22 / r0630 落库之后单独 `try`。
- 榜不可用时只跳过 rr 行，日志写明原因，其他三套照常：
  - 缺 IMP 模型；
  - 快照超过 36 小时或在未来；
  - 某队 total 为 null；
  - 收缩常数不符；
  - 榜抛错。
- 插库每行一个保存点：一行被拒不连累其他行。
- 结算同样各表各自 `try`。

### 评估（预注册）

- 对照：`base`，即线上 Elo 预测，22:00 那次记下。
- 配对：同一场 `base` 与 `rr0630` 都已结算的场次。
- 指标：
  - 配对 log loss 差 Δ = LL(rr0630) − LL(base)；
  - 配对 Brier 差；
  - 逐场配对 bootstrap 95% 区间（`fusionLab.bootstrapCI`，B = 1000）。
- 样本：配对满 **300 场** 才做决定。在此之前页面照常显示进度与当前数字，但不据此做任何改动。
- 决策规则：
  - 300 场以上时，`rr0630` 的 Δlog loss 95% 区间上界 < 0 → 提议把比赛预测切换到阵容+战绩榜，由高磊决定；
  - 否则保留 Elo。
  - Brier 只作佐证，不单独作为切换依据。
- 不因看到中途结果调整参数（K、加权、sd、主场、休息、收缩常数）。要改只能出 params v2：v2 的行从零开始计数，v1 的结果照原规则报告。
- 若影子期内榜的代码改动（`board_code` 变化，例如分钟或缺阵逻辑修正），评估仍按全部行合并，同时按 `board_code` 分段报告改动前后各多少场。
- 盘口不进任何输入，也不进评估。
