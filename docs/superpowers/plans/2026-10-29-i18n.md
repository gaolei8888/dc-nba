# 多语言（i18n）实现计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 整站界面与服务端说明文字可在中文 / 英文间切换，时区作为独立设置，加一种语言只需新增一份语言文件。

**Architecture:** 前端自写轻量翻译层（`web/src/i18n/`）：纯函数核心（查键、插值、复数、回退）+ 每种语言一份 `locales/<lang>.js` + React Provider。服务端不按语言出字，改为返回稳定的 `{ code, params }` 消息，由前端渲染——缓存键与语言无关。时区只影响显示与「今日比赛 / 赛程」分日，从不传给服务端。

**Tech Stack:** React 18 + Vite 6（前端），Node 22 ESM + Express（服务端），`node:test`，`Intl.NumberFormat` / `Intl.DateTimeFormat` / `Intl.PluralRules`；不新增依赖。

**Spec:** `docs/superpowers/specs/2026-10-29-i18n-design.md`（后续依赖：`docs/superpowers/specs/2026-10-29-user-system-design.md`）

## Global Constraints

- 中文为源语言，英文第二；加一种新语言 = 新增一份 `web/src/i18n/locales/<lang>.js`，不改组件代码。
- 默认语言：`navigator.languages` 中 `zh*` → 中文，其他 → 英文；选过的语言存 localStorage（键 `dc-nba:lang`）；支持 `?lang=en`。
- 切换放在侧栏底部现有「深色 / 浅色」切换（`web/src/App.jsx` 的 `.theme-switch`）旁；时区小开关同处。
- 球队名：英文用 `full`（如 `Oklahoma City Thunder`），中文用 `cn`；缩写（BOS 等）两边一致。
- 时区独立设置，默认跟语言：英文 `America/New_York`（ET），中文 `Asia/Shanghai`（北京）；只影响时间显示与「今日比赛」/ 赛程分日；比赛时间显示标明时区。
- 语言、时区不得改变任何数字、结论、预测、账本、影子模式数据；不得进入服务端缓存键。
- 数字用 `Intl.NumberFormat`；比分、评分保留现有小数位；中英文同一数值输出完全相同。
- 缺译文回退中文并在开发环境告警；测试检查 zh/en 键一致。
- 诚实表述英文同样直白（如「无证据表明模型能赢盘口」→ "No evidence the model beats the market"），不得软化。
- 不翻译：docs/、代码注释、提交信息、服务器日志（仍中文）；不做 RTL；同一网址同一部署。
- 项目约定：UI 文案中文为源、注释与提交信息中文、`node:test`、纯计算放模块；部署走 `deploy/README.md`，不覆盖服务器 `docker-compose.yml` 与 `data-db/`。

## Review Focus

- 英文版里残留服务端拼好的中文（错误信息、`label`、结论句、`impactPrior.source`、账本 / 实战不可用原因）——每类都要有 code，前端绝不直接渲染服务端 `error` / `label` / `reason` 字符串（Task 6、7 的扫描测试 + Task 14 浏览器全站扫描）。
- 美国夏令时切换周（2026-11-01）前后，ET 下的比赛日分组与开打时间不能错一小时或错一天（Task 2 的 DST 用例、Task 8 的分组用例）。
- 用户显式选过时区后再切语言，时区不应被语言默认值冲掉；没选过时则跟语言走（Task 3 `resolvePrefs` 用例）。
- localStorage 抛异常（隐私模式）或存了非法语言 / 时区值时，页面照常以默认值启动（Task 3 用例）。
- 同一请求在中 / 英文下的服务端响应字节一致（缓存不分裂、结论不变）；中文渲染结果与改造前逐字相同（Task 7 的中文回归快照）。

**键命名规范：** `<命名空间>.<camelCase>`，命名空间 = 页面文件名小写（`today`、`board`…）或模块（`app`、`nav`、`common`、`fmt`、`team`、`tz`、`err`）；服务端出的内容统一在 `srv.<模块>.*`。为用户系统预留命名空间 `auth.*`（登录页）、`lock.*`（锁定页预告）、`legal.*`（协议），错误码走 `err.*`——本计划不写这些文案，但 Task 6 的错误码机制和 Task 3 的偏好形状就是它们要用的接口。

**插值语法（设计决定）：** `{name}` 原样；`{name, fmt}` 用格式化器，`fmt ∈ int | fix1 | fix2 | fix3 | pct0 | pct1 | signed1 | team | date | dateFull | msg`（`team` 收 teamId，`msg` 收嵌套 `{ code, params }`）。复数：叶子可以是 `{ one, other }`，按 `params.count` 用 `Intl.PluralRules(meta.intl)` 选；中文只写字符串。

**前端测试方式：** 项目没有前端测试框架，也没有 CI 配置（无 `.github/`）。i18n 的纯函数放在不依赖 React / `import.meta.env` 的 `.js` 里，由 `node --test tests/*.test.mjs`（即 `npm test`）直接导入测试；「CI」= `npm test` + `npm run build`（Task 14 把 `check:i18n` 接进 `build`）。

## Spec 中发现的缺口（已在计划中做了设计决定，供用户确认）

- **球员没有中文名**：数据里球员只有英文 `name`（无 `cn`），中文版本来就显示英文名，两边一致；`posCn` 改为按 `pos` 代码翻译。
- **赛程的起止日期筛选**是服务端美东日期口径，而分组改按所选时区——计划保留服务端口径并在筛选框标注「按美东日期」。
- **预测总表的日期列**与「本季实战」的比赛日都按美东日（服务端按美东日锁盘、成绩按美东日汇总），spec 只要求今日比赛 / 赛程按时区分日，这两处不改分组，只翻译标签。
- **时区选项**只做 ET 与北京两个（侧栏小开关）；美国西部用户想要 PT 需另加，`TIMEZONES` 留了扩展位。
- **`?lang=` 是否持久化**：计划定为只作用于本次加载、不写本地存储，避免分享链接改掉对方偏好。
- **排行榜上的玩家名与本地档案名**是用户内容，不翻；服务端默认名「匿名玩家」作为存储数据保留，前端创建时传入本语言默认名。
- **英文表头**只显示缩写、全称放悬停提示（中文保持缩写 + 中文两行）。
- **服务端 `error` / `label` / `reason` 中文字段**保留给脚本与日志，前端只认 `code` / `key`；Task 14 的浏览器扫描是最后一道防线。
