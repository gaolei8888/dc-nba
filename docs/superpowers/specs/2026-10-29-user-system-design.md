# 用户系统设计 — 2026-10-29

## 意图

部分数据和功能只对注册用户开放，但要让未注册的人知道有这些功能。注册对任何人开放。以后可能收费，现在先预留会员等级。
前置项目：多语言框架（2026-10-29-i18n-design.md）。用户系统从第一天起就是中英双语。

用户原话：「有些数据，和功能只对注册用户开放」「预测总表和模拟投注只对注册用户开放」「但是要让他们知道有这个功能」「任何人都可以注册」「手机号收验证码」「你看一下dc-classroom怎么做的」「完全独立，只在 dc-nba 里用」「自动并到新账号里」「不过现在没有用户呢」「你可以按照我们现在的dc_classroom的来做」「要做海外手机号啊」「以后可能收费，先预留会员等级」。
以下除用户原话外，均为设计者（Claude）的决定，标注「设计决定」的可由用户推翻。

## 目标

1. 手机号 + 短信验证码登录，注册与登录合一：新号码验证通过即自动建号，无密码。
2. 支持中国大陆和海外手机号。
3. 「预测总表」页（含其中的「模拟投注」标签页）的汇总统计与模拟投注内容只对登录用户开放；未登录者看到预告。用户选定方案 A：**每场比赛的预测本身仍公开**（赛程、今日比赛、比赛预测页及 `/api/schedule`、`/api/gameday`、`/api/predict`、`/api/live` 不变），锁的是预测总表的汇总统计与模拟投注（命中率、回报、模拟下注记录与历史回测等）。
4. 账号与公司其他产品（课堂、考试等）完全独立，只在 dc-nba 里用。
5. 登录时，浏览器里已有的匿名玩家档案（人机对赌战绩、排行榜身份）自动并入账号。
6. 数据模型预留会员等级，权限按等级判断，今天所有注册用户同一等级。

## 非目标

- 不做密码登录、微信 / 第三方登录、邮箱登录（设计决定）。
- 不做付费、支付、订阅管理；只预留等级字段和按等级判断权限的入口。
- 不和 dc_classroom 等共享用户库或单点登录。
- 不做旧用户迁移：目前没有用户（用户原话「不过现在没有用户呢」）。匿名档案并入只需支持「当前浏览器的档案 → 新账号」这一种简单情形。

## 反目标

- 短信接口可被人拿来狂发短信（每条都要钱、也会骚扰陌生号码）——dc_classroom 现在就是这样（无频率限制、无次数限制、无图形验证），不能照抄。
- 验证码有效期、随机性写错（dc_classroom 有效期单位写错成 5 小时、随机数永远不出 9）。
- 短信发送失败却告诉用户「已发送」。
- 锁定页面只是前端藏起来，接口照样能拿到完整数据——锁定必须在服务端接口上生效。
- 锁定影响到模型本身：预测、账本记录、影子模式、定时任务照常运行，与登录无关。
- 密钥写进代码或提交进仓库。

## 用户可见行为

- **登录入口**：侧栏「当前玩家」区域附近放「登录 / 注册」（设计决定）。登录后显示脱敏手机号（如 138****1234）与退出。
- **登录流程**：选国家 / 地区区号（默认按语言：中文 +86，英文 +1，设计决定）→ 输入手机号 → 勾选同意《用户协议》《隐私政策》→ 获取验证码（60 秒后可重发）→ 输入 6 位验证码 → 进入。新号码自动建号。
- **锁定页预告**：侧栏照常显示「预测总表」并加锁标；页内「模拟投注」标签也加锁标（「模拟投注」不是独立侧栏页，是 web/src/pages/Board.jsx 里的 `bet` 标签）。点进去：显示页面顶部的一句话总结和少量公开统计（实现者从现有页面中挑，例如样本量），下方内容模糊遮挡，盖一个「登录后查看完整战绩统计与模拟投注」按钮。提示文字不得写成「登录后查看今晚的预测」——每场预测在别处公开（设计决定，用户可调整露出哪些）。
- **档案并入**：一个账号对应一个玩家档案（设计决定）。登录时，浏览器里**当前在用**的匿名档案（现有 Bearer 排行榜令牌 / 浏览器档案，见 server/index.mjs 约 L468–520 的 `requireAuth`、`/api/me`，以及 web/src/lib/profiles.js 的多档案）绑定到账号；若账号已有档案，以账号的为准，这台设备的匿名记录不并入（设计决定；目前无用户，此情形罕见）。换设备登录后看到账号的同一档案与战绩。
- **登录状态**：保持 30 天（设计决定）。
- **多语言**：登录页、锁定页、错误提示都有中英文。短信内容只发中文（用户决定：沿用已审批的腾讯云中文模板，不另申请英文模板）。

## 短信

- **国内号（+86）**：沿用 dc_classroom 的腾讯云短信账号、签名「上海磊宁科技有限公司」和已审批的验证码模板（dc-common `TencentSmsService.groovy`：SdkAppId 1400683809，TemplateId 1417875，参数 `[code, '1']`）。dc-nba 是 Node，直接调腾讯云短信 API，不依赖 Grails 代码。实现者核对模板正文里的有效期参数，和我们的有效期一致。
- **海外号**：走 Twilio Verify（设计决定：美国运营商对验证码短信有专门合规要求，Twilio Verify 送达更可靠）。公司尚无 Twilio 账号，用户决定**先关闭海外**：代码与界面做好，但默认关闭（开关控制，关闭时区号只能选 +86，并提示海外号即将开放），账号开好后再打开。Twilio Verify 的短信文字由 Twilio 按地区生成，我们不提供文案。
- **密钥**：从环境变量读取（腾讯云沿用 dc_classroom 的变量名 `TENCENT_SMS_SECRET_ID` / `TENCENT_SMS_SECRET_KEY` 等），放服务器 compose 的环境里，不进仓库。
- **安全前提**：dc_classroom 配置注释说旧的短信密钥曾提交到 Gitee、需要更换。上线前须确认腾讯云后台已轮换。

## 防刷与安全（设计决定）

- 验证码 6 位，用加密安全的随机数；有效期 5 分钟；只存哈希；验证成功或错 5 次即作废。
- 同一号码 60 秒一次、每天最多 10 次；同一 IP 每小时、每天各有上限；全站每日发送总量上限默认 500 条（设计决定，可配置），超限停发、写服务器日志并在健康检查里报警。
- 网站经 `/works/` 网关（Traefik）转发：按 IP 限频必须配置 Express `trust proxy`，取真实访客地址，否则所有访客共用一个限额。
- 发送失败如实报错，不缓存验证码。
- 必要时加图形验证或滑块（实现者判断是否首版就做；至少在触发频率限制后出现）。
- 登录凭证用 Bearer 令牌，与现有排行榜令牌机制一致（设计决定：web/src/lib/profiles.js 注释指出 `/works/` 网关双向去掉 cookie，cookie 方案不可行；实现者先核实）；服务端只存令牌哈希，退出即失效。
- 手机号按 E.164 规范化存储，同一号码只能有一个账号。

## 会员等级（预留）

- 账号带等级字段（如 `free`），以及到期时间等以后付费会用的字段（实现者定）。
- 服务端有一处统一的「这个用户能不能看 X」判断，按等级配置；今天「预测总表」「模拟投注」对所有登录用户开放。
- 不做任何付费、支付界面。

## 约束

- 存储用现有 SQLite（data-db/app.db，卷持久化）；新表用 `CREATE TABLE IF NOT EXISTS` 迁移；不覆盖服务器 data-db/ 与 docker-compose.yml。
- 现有匿名玩法（人机对赌、排行榜）不登录也照常能用（设计决定）。
- 锁定只作用于预测总表页（含模拟投注标签）用到的接口——`/api/predictions/summary`、`/api/paper` 等，实现者核对 Board.jsx 实际调用的全部接口；其他接口保持公开。被锁接口对未登录请求只返回预告所需的公开字段。
- 按国内规定准备《用户协议》《隐私政策》（中英文）；内容由实现者起草，用户审定。
- 代码风格、测试、部署沿用项目约定（node:test、中文注释、deploy/README.md、回滚标签、数据库备份）。
