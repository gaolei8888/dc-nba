# 多语言（i18n）设计 — 2026-10-29

## 意图

用户要做一版英文网站，并要求「支持 i18n」：先中文和英文，以后再加其他语言。
英文版面向海外（以美国等英语地区为主）的 NBA 观众；随后的用户系统（见 2026-10-29-user-system-design.md）也要从第一天起就是中英双语，所以先做多语言框架。

用户原话：「这个网站我们要做一版英文版」「我们要支持i18n」「先中文和英文，以后再加」。
以下除用户原话外，均为设计者（Claude）的决定，标注「设计决定」的可由用户推翻。

## 目标

1. 整站界面可在中文 / 英文之间切换：菜单、按钮、表头、提示、空状态、错误信息、页面里的说明文字、图表标签。
2. 加一种新语言只需新增一份语言文件，不改业务代码。
3. 服务端生成的、会显示给用户的文字（结论句、错误信息、说明字段）也跟随语言。
4. 数字、百分比、日期和比赛时间按语言 / 地区格式显示。

## 非目标

- 不翻译内部资料：docs/ 下的实验结论、交接文档、代码注释、提交信息、服务器日志仍用中文。
- 不另开英文域名或子站；同一网址、同一套部署（设计决定）。
- 不做机器实时翻译；所有界面文字由人（或 Claude）事先写好译文入库。
- 不做从右到左（RTL）语言支持；以后真要加再说。

## 反目标（技术上能跑，但算失败）

- 英文版里夹着漏翻的中文（尤其是服务端返回的结论句、按钮提示、表头缩写说明）。
- 切换语言后数字或结论变了——语言只能改显示，不能改任何计算或预测。
- 为了翻译把模型口径改写得更「好听」：页面上的诚实表述（如「无证据表明模型能赢盘口」「未经回测验证」）英文版必须同样直白。
- 加新语言要改组件代码。

## 用户可见行为

- **切换**：侧栏底部（现有「深色 / 浅色」切换旁）放「中文 / EN」切换（设计决定）。选过的语言记在浏览器本地；用户系统上线后，登录用户的语言同时存进账号。
- **默认语言**：第一次访问按浏览器语言（`navigator.languages`）选，`zh*` → 中文，其他 → 英文（设计决定）。
- **网址**：同一网址；可选支持 `?lang=en` 便于分享（设计决定，留给实现者决定是否做）。
- **球队与球员名**：英文版用英文全名（数据里已有 `full` / `name`），中文版沿用中文名（`cn`）。缩写（BOS 等）两边一致。
- **时间**：时区是独立设置，默认跟语言走——英文美东时间（ET），中文北京时间——可单独切换（侧栏语言切换旁的小开关，设计决定）；登录用户存进账号。时区影响时间显示和「今日比赛」/赛程按哪天分组（现有 `bjTimeOf` 等北京时间辅助函数需改为按所选时区），不影响任何预测、账本或影子模式数据。比赛时间显示标明时区。
- **数字**：千分位、小数、百分比用 `Intl.NumberFormat` 按语言；比分、评分保留现有小数位。

## 范围（已知需要处理的文字来源）

1. 前端 `web/src`：App.jsx、components/、12 个页面（约 4600 行 JSX，中文字符串内联）。
2. 服务端返回给前端显示的中文：例如 `/api/meta` 的说明字段、`/api/predictions/summary` 与 `/api/paper` 的一句话结论、`/api/shadow` 的说明、错误信息（`res.status(400).json({ error: '…' })`）、阵容榜 `impactPrior.source` 这类说明字符串。
3. 数据里的中文：球队 `cn`、球员 `posCn`、`teamCn` 等。
4. 以后用户系统的短信内容、登录页、锁定页。

## 设计决定（可推翻）

- 服务端文字：服务端返回**稳定的消息键 + 参数**（如 `{ code: 'paper.noEvidence', params: { n, roi, lo, hi } }`），由前端按语言渲染；或者服务端按请求语言（`Accept-Language` / `?lang`）直接返回对应文字。实现者二选一，但同一类文字要统一；倾向前者，便于缓存（现有 `/api/rankings` 等有按参数缓存）。
- 语言文件按页面 / 模块分组，中文为源语言；缺译文时回退中文并在开发环境告警，CI 测试检查两份语言文件键一致。
- 不新增依赖优先；若自写的轻量翻译函数明显不够（复数、插值、嵌套），可引入一个成熟的小库，须说明理由。

## 约束

- 现有约定：UI 中文、代码注释和提交信息中文、node:test 测试、纯计算放 server 模块。
- 语言切换不得影响任何计算、缓存键以外的服务端行为；预测、账本、影子模式数据一律与语言无关。
- 部署走 deploy/README.md；不覆盖服务器 docker-compose.yml 与 data-db/。

## 留给实现者

- 抽取字符串的工具与流程、语言文件格式与目录、键的命名规范。
- 英文译文初稿由实现者写，篮球术语用美国通行说法（e.g. Net Rating、On/Off、Back-to-back）；实现者列出拿不准的术语清单供用户过目。
- 分批迁移的顺序（建议先框架 + 侧栏 + 一个页面打样，再逐页迁移）。
