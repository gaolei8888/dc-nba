# 独赢盘投注回测与策略评估设计 — 2026-10-29

## 意图

回答一个问题：**模型相对赔率市场有没有可持续的优势**——用当时真实可获得的价格、可复现的逐注流水和带置信区间的统计，证明或证伪，而不是调出好看的历史收益。

用户原话与来源：
- 用户任务说明「升级体育预测系统的投注收益回测与策略评估」（2026-10-29，本会话）。
- `docs/nba-betting-quant-research.md`（用户提交，P0→P3 顺序、验收标准、优先独赢盘）。
- `docs/superpowers/specs/2026-10-29-betting-backtest-analysis.md`（现状审计）。
- 用户决定：「先只做独赢盘，底层问题先修」。

以下除上述来源外，均为设计者（Claude）的决定，标注「设计决定」的可由用户推翻。

## 目标

1. **底层修复（先做）**：回测结果可信的前提。
2. **独赢盘逐注回测**：赔率换算、去水、Edge、EV、结算、资金曲线、ROI、CLV。
3. **策略比较**：无筛选基准、Edge 阈值、正 EV、分数 Kelly；参数只在训练/验证期选，测试期锁定。
4. **风险与显著性**：回撤、连亏、分桶 ROI、校准、按比赛日 / 赛季的 block bootstrap 区间、多重比较提示、样本量提示。
5. **页面**：模型实验室新增「模型能否打败市场？」标签页（中英双语）。
6. **报告**：一份技术说明 + 一份真实回测报告，回答用户列出的六个问题（见「报告」）。

## 非目标

- 让分盘、大小分：本期不做（不重抓历史赔价）。数据结构与结算模块按「市场」抽象，留扩展口，但不实现、不展示。
- 不接任何真实投注账户、不下真钱、不自动下单。
- 不接付费赔率接口（The Odds API、Betfair 历史数据等）——若后续需要，停下上报。
- 不改线上比赛预测所用的生产模型（Elo）；底层修复只作用于回测 / 重放路径，除非修复本身证明生产模型参数有误（届时单独上报）。

## 反目标

- 用当前赔率冒充历史赔率；用统一 -110 或任何假设价格算出的收益被称为「历史实际 ROI」。
- 在测试集上挑参数、挑策略、挑分组后报告其收益。
- 把 Edge 当 ROI；把命中率当盈利。
- 资金管理（Kelly）掩盖没有预测优势的事实。
- 56 场（本季）或任何小样本结果被写成「长期盈利」。
- 补造、插值、平滑任何历史数据。

## 已知数据事实（来自现状审计）

- 历史独赢盘：`data/history/books_<season>.json`，2021-22～2025-26 每季 1230 场全覆盖，多家博彩公司。时点：2021-22 只有 current；2022-23 多为 current；2023-24 起有 open / close / current。**无报价采集时间戳，无历史开赛时间**。2024-25 只有 ESPN BET；2025-26 起只有 DraftKings。
- 本季（2026-27）前向账本 `paper_bets`：22:00 / 06:30（北京）赛前记录 DK 价格，带记录时间与开赛时间——这是唯一真正「决策时点可得」的价格，样本小。
- 重放模型（`server/lab.mjs` replay）只含 Elo + 主场 + 休息；线上还含阵容 / 伤病修正。
- `spreadSd = 12` 未拟合，实际残差 SD 12.9–14.6，胜率可能过于自信。

## 一、底层修复（第一阶段，先于一切回测）

1. **同日泄漏**：重放时同一比赛日按 gameId 顺序更新 Elo，后打的比赛用到了先打完那场的结果。修复：每个比赛日先算完当日全部赛前预测，再统一更新。用测试钉住：同日两场，第二场的赛前评分不受第一场结果影响。
2. **参数时间外选择（walk-forward）**：主场优势、休息权重、胜率换算所用分差 SD（及任何回测路径用到的可调参数）对每个测试赛季只用此前赛季拟合。报告每季拟合出的参数，以及与当前全局参数的差异。生产参数是否需要调整，单独上报，不在本项目中改线上。
3. **概率校准**：在 walk-forward 下拟合胜率换算（SD 或逻辑斯蒂刻度），用可靠性曲线 / Brier / Log Loss 检验；模型概率是 Edge、EV、Kelly 的输入，必须先校准。
4. **价格时点标注**：每笔历史模拟下注记录所用价格时点（open / current / close）与来源博彩公司。默认情景（设计决定）：
   - 「开盘价情景」：有 open 的赛季（2023-24 起）用 open 下注、close 计 CLV——最接近赛前较早决策；
   - 「收盘价情景」：所有赛季用 close（缺 close 用 current，并标注），明确写「以收盘价模拟，不代表更早决策时能成交」；
   - 两个情景分开报告，不合并。
5. **数据完整性检查**：重复比赛、重复下注、缺价、异常赔率（如 −100000 的滚球价、离谱线）、主客颠倒、结算错误；输出覆盖率与缺失率。
6. **复核 49.1%**：找出 README 让分命中率 49.1% 的计算口径与样本定义，写进报告（属于核对已有说法，不扩展让分盘功能）。

## 二、独赢盘回测

- 换算：美式 ↔ 十进制；盈亏平衡概率（+A：100/(A+100)；−A：A/(A+100)）；双侧去水公平概率（同一时点、同一博彩公司）。
- `edge = p_model − p_break_even`（按实际下注价格）；`EV/单位 = p_model × (decimal − 1) − (1 − p_model)`。去水概率只用于比较模型与市场谁更准，收益一律按实际报价结算。
- 结算：胜 / 负 / 作废（延期、取消，规则可配置；NBA 无平局）。
- 每笔记录：比赛 ID、比赛日、主客队、模型版本与参数版本、决策时点（历史为「情景」标签）、方向、p_model、赔率、盘口时点、博彩公司、下注金额、结果、净利润、CLV。
- 汇总：投注数、总下注额、净利润、ROI（总净利润 / 总下注额）、胜率、平均赔率、最大回撤及持续时间、最长连亏、盈利月份比例、资金曲线。
- 可配置成本假设：手续费、滑点（按美式赔率点数或概率）、单注限额；默认 0，并在报告中给出敏感性（如滑点 0 / 5 / 10 点）。
- 同一数据与参数重复运行，逐注流水与 ROI 完全一致。

## 三、策略

- A 基准：每场固定金额押模型看好的一方（及「押主队」「押热门」等朴素对照，设计决定）。
- B Edge 阈值：2% / 3% / 5% / 7% / 10%。
- C 正 EV：EV > 0 且数据质量合格（有价、价格时点符合情景）。
- D Kelly：Full / Half / Quarter，单注上限（默认本金 5%，可配置），不允许负仓位或杠杆。
- 默认以固定金额比较策略；Kelly 只用于比较资金管理效果。
- **数据切分（设计决定）**：Elo 预热 2021-22；滚动：用 ≤N−1 赛季选参数，在 N 赛季验证；最终独立测试期 2025-26 及本季前向账本——测试期参数锁定，只报告一次。报告同时列出训练 / 验证 / 测试三段结果，以及尝试过的全部策略与参数（多重比较）。

## 四、风险与显著性

- Block bootstrap：按比赛日（主）与按赛季（辅）重采样，给 ROI 与 Edge 的 95% 区间。
- 分桶：赔率区间、Edge 区间、模型概率区间、主客、背靠背、赛季阶段的 ROI 与样本数——分组只作可验证假设，不在测试集挑出盈利组宣称有效。
- 校准：Brier、Log Loss、可靠性曲线，模型 vs 去水市场概率对比。
- 样本量提示：样本不足时显示明确警告；报告给出「需要多少额外样本才能在给定效应下显著」的估算（设计决定：按观测到的 ROI 方差做功效分析）。

## 五、页面（模型实验室新标签「模型能否打败市场？」）

- 设计决定：放在模型实验室（与研究文档一致），预测总表现有的「模拟投注」区保留不动。
- 顶部：总投注数、总下注额、净利润、ROI（带区间）、胜率、最大回撤、平均 CLV。
- 图：累计资金曲线、策略 ROI 比较（带区间）、Edge 区间 vs 实际盈利、校准图。
- 筛选：价格情景（开盘 / 收盘 / 本季前向账本）、日期范围 / 赛季、模型版本、博彩公司、策略、数据切分（训练 / 验证 / 测试）。
- 默认显示独立测试期结果；明确区分「历史价格情景模拟」与「本季前向账本（决策时点真实价格）」；缺价或价格时点不符时显示警告。
- 中英双语，沿用已上线的 i18n 框架（`t()`、`fmt`、服务端 `{code, params}`），诚实表述英文同样直白。

## 审阅后补充的决定（设计决定，均可推翻）

1. **价格与博彩公司**：只用美国博彩公司（`server/books.mjs` 的 `US_BOOKS`），Betfair 等交易所不用于下注定价。每场按固定优先级取一家：DraftKings → ESPN BET → BetMGM → Caesars → 其他美国公司；该场若没有任何美国公司报价则跳过并计入缺失率。按博彩公司分别给出覆盖率与结果。「挑最优价」只作为单独标注的敏感性情景（事后挑价有利偏差），不进主结论。
2. **数据切分与诚实标注**：
   - 2021-22 只作 Elo 预热。
   - 收盘价情景：2022-23～2024-25 滚动选参（每季只用此前赛季）与验证；2025-26 为测试期，**但报告必须注明它已在此前的分析中被看过**（`paper-backtest`、49.1%、edge 规则都用过），不是完全干净的测试。
   - 开盘价情景：只有 2023-24 起有 open，选参用 2023-24，验证 2024-25，测试 2025-26；样本小，照实写。
   - **真正干净的检验是本季（2026-27）前向账本**：参数在开始实施前冻结，报告单列。
3. **重放修复的范围**：同日泄漏是缺陷，**全局修复**（`server/lab.mjs` 重放、`data/backtest.json`、README 中受影响的数字一并重算并更新），新旧数字差异写进报告。walk-forward 选参作为回测的新路径加入，不改线上生产参数；若结果表明生产参数应调整，单独上报。
4. **两种模型分开报告，绝不合并**：历史回测评估的是「重放模型」（Elo + 主场 + 休息，校准后）；前向账本评估的是「线上生产模型」，概率按当时记录原样使用、不事后重新校准。页面的「模型版本」筛选区分二者。
5. **结论标准（预先写定）**：「有证据表明能赢盘口」需同时满足：测试期扣除默认成本后 ROI 的 95% block bootstrap 区间下界 > 0，且投注数 ≥ 300；前向账本另需 ≥ 300 注且同样区间下界 > 0。否则结论写「无证据」，并给出功效分析：按观测方差，达到显著需要多少注。预期诚实结论很可能是「目前无法判断 / 无证据」，这是可接受的结论。
