# 预注册：伤病感知 Elo 的影子运行（inj-p1 / inj-a）前向评估

- 写于 **2026-10-29**，分支 `injury-elo`，在任何前向影子数据产生之前。本文件先单独提交，之后才写影子代码。
- 影子期内不改本文件。若必须偏离，只在文末追加带日期的「偏离」一节，写明原因。
- 背景：`docs/injury-aware-elo-verdict.md`（回测按预注册规则勉强通过；独立审阅认为只能当假设）。
- 批准范围：**只做影子**。线上预测、页面、模拟投注账本规则、所有冻结参数都不改。切换线上需要另行批准。

## 记什么

两个候选方案，挂在现有影子运行（`scripts/shadow.mjs`）的同一次运行里，北京 22:00 与 06:30（`--late`）两个时点，与 `base` / `r0630` / `rr0630` 同一时机记、同一方式结算。

- **inj-p1**：P1，β = 0.5。胜率 = Φ((base 净胜分 − 0.5·(D_pre主 − D_pre客)) / 12)。
  - base 净胜分 = 同一场 `shadow_predictions` 的 `base` 行（22:00 记）。06:30 那次与 `r0630` 一样沿用 22:00 的 base；没有就用此刻的线上预测。
- **inj-a**：A，s = 0.75。胜率 = Φ((base 净胜分 + (ΔElo_A − ΔElo_P)/28 − 0.75·(D_pre主 − D_pre客)) / 12)。
  - ΔElo_A = 主客的伤病感知 Elo 之差，ΔElo_P = 生产口径 Elo 之差，二者都只用比赛日（美东）之前的赛果。
  - 这样 base 里除 Elo 之外的各项（主场、休息、阵容更迭项）原样保留，只把生产 Elo 换成伤病感知 Elo。
- 每个方案两个变体：`*-22`（北京 22:00 那次能看到的报告）与 `*-0630`（北京 06:30 那次）。06:30 之前开打的场在 22:00 那次就记 `*-0630`，规则与 `r0630` 相同。
- **主变体是 `inj-p1-0630` 与 `inj-a-0630`**，与回测的 06:30 报告链同口径。`*-22` 只报告。

### 冻结参数（`server/injury-elo-params-v1.json`，version 1）

都来自回测，影子期内不调：

- s = 0.75，β = 0.5，sd = 12，报告延迟 15 分钟，ELO_PER_POINT = 28，K = 20。
- P(出场 | 状态)：回测五季（2021-22..2025-26）合起来的表（即 `npm run lab:injury-elo` 里的 `pTable(ALL)`）。
- 球员价值：收缩 IMP `valuesUpto('2025-26')`（只含 2025-26 及更早），本季新人等查不到的按替补级 −0.5。
- A 的开季 Elo：2025-26 用 A 规则（s = 0.75，D_post 来自 stints）逐场跑完再保留 0.75。冻结时核对 D=0 时的开季 Elo 与线上 `eloPreseasonExact` 一致。
- 健康基线：同回测（本季为该队上过场、之后没去别队；近 10 场上过或在本场赛前报告链上；分钟 = 最近至多 10 次为本队出场的场均；本队本季少于 3 场有出场数据时 H 为空、D = 0）。

### 与回测的已知差别（预先声明）

1. **本季 Elo 逐场更新，不按日分组**。线上 `computeElo` 就是逐场的；这样 D_post 全为 0 时 A 的 Elo 与线上 Elo 逐位相同。回测的 `replayElo` 按日分组（与 `lab.replay` 同）。
2. **赛前扣分只看赛前报告**。回测在没有 stints 的比赛上把 D_pre 也记 0（审阅 M3），影子不这样做。
3. 报告姓名匹配用 `player-values.json` 的姓名表（与 `r0630` 同），不是 `impact_*.json`。
4. 过去比赛的健康基线里「在赛前报告链上」这一条，用库里存过的报告（`injury_reports`，影子运行每次抓的那几份）。库里没有那天的报告时，只用「近 10 场上过」，并计入审计。

## D_post 的数据来源与覆盖

- 来源：`data/player-values.json`（GB10 每天由 `scripts/player-values.mjs` 生成并推到服务器，烤进镜像；与 `r0630` 用的是同一个文件）。里面每队每场的球员分钟来自本季 play-by-play 还原的 stints，**不新增任何 stats.nba.com 请求**。
- 全季逐场分钟在新字段 `played`；旧文件只有 `recent`（每队最近 12 场），读不到 `played` 时用 `recent`，超出 12 场的比赛就算「缺」。
- **每行 inj-a 都记**：
  - 两队本季已赛场数、其中有出场数据的场数、覆盖率（有 / 已赛）；缺数据的 gameId 列表；
  - `results_through`（用到的最后一个赛果日期，必须早于比赛日）；
  - player-values 的生成时间、数据快照时间、用到的报告名与标注时间。
- 缺数据的比赛在 A 的更新里两队 D_post 记 0（回测同），**但必须在行里可见**：覆盖率 < 1 的行就是受影响的行。

## 赛前性（库里兜底 + 单测）

- 用到的每份报告：标注时间 + 15 分钟 ≤ captured_at，且标注时间 < 开赛。
- 开赛时间缺失：不记（保守分支），只记日志。
- 健康基线、D_post、Elo 只用比赛日（美东）之前的数据；同日早场的出场与赛果不进同日晚场。
- 开赛后插不进（按真实时钟），且 captured_at < tipoff_utc。
- `results_through < game_date`。
- 表只追加：重复忽略、不能删、预测与输入字段不能改、比分只写一次。

## 评估

### 何时看

只看两次，中间不看显著性（`show` / 接口可以随时显示进度与点估计，但决策只在这两次做）：

1. **中期检查**：三套主变体（`base`、`inj-p1-0630`、`inj-a-0630`）都已结算的共同场数**第一次 ≥ 300** 时。只用来查实现问题与明显伤害，不做切换决定。
2. **最终评估**：2026-27 常规赛结束后（全部常规赛结算完）。切换建议只在这一次做。

### 指标与区间

- 主指标：配对 Δ log loss（逐场 −log p），在三套主变体共同结算的比赛上算。另报 Brier Δ 与命中率。
- 区间：**按比赛日（美东 game_date）分块的 bootstrap**，B = 2000，seed = 7，95% 百分位区间。
- 对比：
  - (1) **inj-a − inj-p1**（A 是否优于 P1，主问题）；
  - (2) inj-p1 − base（默认是否扣伤病）；
  - (3) inj-a − base。
- 同表另报 `rr0630`（阵容+战绩榜）在同一批场次上的 log loss 与 Brier，只作参照。
- 分组（只报告）：两队 D_post 覆盖率都 = 1 的行 vs 其余；`*-22` 变体。

### 功效（预先说明，免得事后解读）

- 回测里 A − P1 的逐场差的标准差约 0.046（由 4920 场的区间宽度反推），P1 − P0 约 0.07。
- 300 场时 A − P1 的 95% 区间半宽约 0.005，全季约 1150 场时约 0.0027。回测的效应只有 −0.0014，去掉 2022-23 只有 −0.0006。
- **所以前向数据单独很可能不显著。预期结果就是「不切换」。**这是预先接受的结果，不能因此放宽阈值、延长或改口径。

### 决策规则

**中期检查（≥ 300 场）**：

- 若 inj-a − base 的区间下界 > 0（A 显著差于线上），或 inj-a 行的 D_post 覆盖率低于 90%（按队·场），记一条「实现/数据问题」，排查后继续记录；不改参数。
- 其余情况照常继续，不下结论。

**最终评估（常规赛结束）**，建议切换线上（仍需高磊批准）的条件：

- **改用 A（inj-a）**，同时满足：
  1. inj-a − inj-p1 的按日分块 95% 区间上界 < 0；
  2. inj-a − base 的点估计 < 0；
  3. Brier Δ（inj-a − inj-p1）点估计 ≤ 0；
  4. inj-a 行中两队 D_post 覆盖率都 = 1 的比赛占 ≥ 90%，并且只看这些比赛时 (1) 的点估计仍 < 0。
- **只改用 P1（默认扣伤病，不换 Elo）**：A 不满足上面的条件，但 inj-p1 − base 的区间上界 < 0，且 Brier Δ 点估计 ≤ 0。
  - 这与现有伤病报告影子（`r0630`，RAPM）回答的是同一个问题，结论要与它的前向结果一起写，二者冲突时不切换。
- **都不满足：不切换**，照实写「不采纳」，结果为零就说是零。
